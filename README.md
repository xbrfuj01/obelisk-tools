# Obelisk

Набір веб-інструментів, що самостійно хоститься через Docker Compose:

- **Завантажувач відео** — YouTube, Instagram, VK, TikTok та інші сайти, підтримувані [yt-dlp](https://github.com/yt-dlp/yt-dlp).
- **Конвертер відео** — приведення файлу до кодека/контейнера, сумісного з відеоредакторами (напр. Premiere), із авто-визначенням, чи конвертація взагалі потрібна.
- **Редактор метаданих** — показує всі приховані метадані будь-якого файлу (фото, відео, аудіо, PDF, документи) і робить чисту копію без них.

Розрахований і на локальну мережу, і на роботу у відкритому інтернеті (див. розділ "Захист доступу" нижче).

`docker-compose.yml` не містить жодної змінної середовища — все налаштовується прямо в адмінці після запуску.

## Можливості

- Сторінка-хаб після входу — вибір потрібного інструменту.
- Завантаження відео: вставити посилання, вибрати тип завантаження (відео+аудіо / лише відео / лише аудіо), якість (підтягується автоматично з реального відео), формат файлу, субтитри, вирізання фрагмента за таймкодами.
- Автоматична перевірка сумісності з відеоредакторами одразу після завантаження — і, за потреби, автоконвертація без зайвих кліків.
- Прогрес завантаження/конвертації в реальному часі, стрічка останніх завдань з пагінацією.
- Вхід на сайт (логін+пароль, окремо від адмінки) — сесія "запам'ятовується" на пристрої, блокування після кількох невдалих спроб.
- Персональні сповіщення від адміна конкретному користувачу (спливають один раз при наступному візиті).
- Світла/темна/системна тема оформлення.
- Адмін-панель під логіном/паролем: статистика (з кільцевими індикаторами навантаження сервера), окрема вкладка "Історія" (завантаження й конвертації), керування користувачами й нотатками про них, і **всі** налаштування сервісу (нижче).
- Cookies акаунта YouTube (опційно) — для відео, які YouTube віддає лише авторизованим користувачам.
- Автоматичне видалення застарілих файлів через N годин, і кнопка миттєвого повного очищення історії.
- Захист від SSRF (заборона посилань на приватні/локальні адреси) та обмеження частоти запитів на завантаження.

## Як це працює

Образ автоматично збирається GitHub Actions ([.github/workflows/docker-publish.yml](.github/workflows/docker-publish.yml)) при кожному push у `main` і публікується в GitHub Container Registry: `ghcr.io/xbrfuj01/obelisk:latest`. `docker-compose.yml` посилається саме на цей готовий образ (`image:`, без `build:`) — тому на сервері **не потрібен ні git, ні вихідний код**, лише сам `docker-compose.yml`.

Для YouTube образ разом з `obelisk` піднімає й другий контейнер, **`bgutil-provider`** — він генерує "proof of origin" токен, якого YouTube зараз вимагає від будь-якого клієнта (включно з `yt-dlp`), інакше видає лише обмежену якість або відмовляє повністю. Обидва сервіси вже описані в `docker-compose.yml`, окремо піднімати нічого не треба.

## Запуск (Docker Compose / Dockge)

1. У Dockge (або будь-де, де ви керуєте Docker Compose стеками) створіть новий стек і вставте туди вміст [docker-compose.yml](docker-compose.yml) з цього репозиторію — жодних змінних середовища заповнювати не потрібно.

2. Одноразово: зробіть пакет `obelisk` у GHCR публічним, щоб Dockge міг стягнути образ без логіну — на GitHub відкрийте свій профіль → вкладка **Packages** → `obelisk` → **Package settings** → **Change visibility** → **Public**. (Якщо лишити приватним — доведеться один раз виконати `docker login ghcr.io` на сервері з Personal Access Token, що має право `read:packages`.)

3. Натисніть **Deploy**.

4. Відкрийте `http://<IP-сервера>:30301` — одразу відкриється хаб із вибором інструменту (вхід на сайт вимкнений, поки ви самі не увімкнете його в адмінці). Адмінка: `http://<IP-сервера>:30301/admin`, логін/пароль за замовчуванням — **`admin`/`admin`. Обов'язково змініть одразу** в розділі "Налаштування".

### Оновлення

Коли в коді з'являються зміни (я їх пушу в `main`) — GitHub сам збирає новий образ за кілька хвилин. На сервері просто натисніть у Dockge **Pull** (стягнути новий образ), потім **Update/Restart** — без git і без ручних команд.

## Налаштування — все в адмінці

Після першого входу в `/admin` → розділ "Налаштування" можна керувати всім:

| Налаштування | За замовчуванням | Приміт |
|---|---|---|
| Логін/пароль адміна | `admin` / `admin` | Змінити одразу після першого запуску |
| Логін/пароль сайту | вимкнено | Задайте, щоб закрити сайт паролем (обов'язково перед виходом в інтернет) |
| Автовидалення файлів (годин) | 24 | |
| Перевірка застарілих файлів (хвилин) | 30 | |
| Максимум одночасних завантажень | 2 | Діє одразу, без перезапуску |
| Максимум одночасних конвертацій | 1 | Діє одразу, без перезапуску |
| Максимальний розмір файлу для конвертера (МБ) | 2048 | |
| Тривалість сесії на пристрої (днів) | 30 | Застосується після перезапуску контейнера |
| Часовий пояс (для дат в адмінці) | Europe/Kyiv | |
| Проксі (URL + домени) | вимкнено | Для сайтів, заблокованих у вашій країні — див. розділ нижче |

`SECRET_KEY` для підпису сесійних cookie генерується автоматично при першому запуску й зберігається в базі — його ніде не потрібно вказувати.

## Захист доступу (готовність до відкритого інтернету)

За замовчуванням сайт відкритий для будь-кого, хто до нього достукається — це нормально, поки він доступний лише у вашій LAN. **Якщо плануєте відкрити сайт у публічний доступ (в інтернет)** — обов'язково задайте пароль сайту в адмінці, інакше будь-хто зможе завантажувати відео вашим сервером і забивати диск.

Що вже вбудовано для роботи у відкритому інтернеті:

- **Вхід на сайт** (логін+пароль) — вмикається/змінюється в адмінці, після цього на сайті з'являється сторінка входу.
- **Довга сесія** — вхід "запам'ятовується" на пристрої (за замовчуванням 30 днів) через підписану cookie, не треба вводити пароль щоразу.
- **Блокування брутфорсу** — після 5 невдалих спроб (вхід на сайт і в адмінку рахуються окремо) IP-адреса блокується на 15 хвилин.
- **Захист від SSRF** — сервіс відмовляється завантажувати посилання, які вказують на приватні/локальні IP-адреси (10.x, 192.168.x, 127.0.0.1 тощо), щоб форму не можна було використати для сканування вашої домашньої мережі зсередини.
- **Обмеження частоти завантажень** — не більше 20 нових завантажень за 10 хвилин з однієї IP-адреси, щоб не забивали диск флудом запитів.

Навіть з усім цим **обов'язково додайте HTTPS** перед виходом в інтернет (reverse proxy на кшталт Caddy/Traefik/nginx з TLS, або тунель на кшталт вашого Pangolin, якщо він сам термінує TLS) — без цього пароль і сесійні cookie йдуть мережею у відкритому вигляді.

## Обхід блокування окремих сайтів (VK, RuTube тощо)

Якщо якісь сайти недоступні напряму з вашої мережі (наприклад, заблоковані на рівні країни), можна прогнати запити лише до цих доменів через проксі-сервер, лишивши решту завантажень (YouTube, Instagram, TikTok) без змін.

1. На зовнішньому сервері (VPS), доступному з інтернету, підніміть легкий SOCKS5-проксі, наприклад [microsocks](https://github.com/rofl0r/microsocks) (один бінарник, без залежностей):

   ```bash
   git clone https://github.com/rofl0r/microsocks.git
   cd microsocks && make
   ./microsocks -1 -u myuser -P mypassword -p 1080 &
   ```

   `-1` вмикає обов'язкову автентифікацію (`-u`/`-P`) — проксі дивиться в інтернет, тож без пароля ним зможе скористатись будь-хто, хто знає IP. Відкрийте порт `1080` у фаєрволі VPS лише для потрібних цілей.

2. В адмінці, розділ "Налаштування" → "Проксі для заблокованих сайтів", вкажіть:
   - **Адреса проксі**: `socks5h://myuser:mypassword@<IP-або-хост-VPS>:1080` (саме `socks5h`, а не `socks5` — інакше DNS резолвиться локально й може не спрацювати для заблокованих доменів)
   - **Домени через проксі**: за замовчуванням там уже основні російські відеосервіси (`vk.com,vk.ru,vkvideo.ru,ok.ru,rutube.ru,mail.ru`) — можна лишити як є або відредагувати.

3. Збережіть. Діє одразу, без перезапуску контейнера. Тепер запити саме до цих доменів підуть через VPS, а самі файли, як і раніше, зберігаються на вашому домашньому сервері — через проксі йде лише мережевий трафік завантаження, не сховище.

## Дані

- `/mnt/apps/obelisk/downloads` — завантажені файли (том, монтується в контейнер як `/downloads`).
- `/mnt/apps/obelisk/data` — SQLite база з історією та всіма налаштуваннями, а також `cookies.txt`, якщо задано (том, монтується як `/data`).

## Важливо

- Перш ніж відкривати сервіс в інтернет — задайте пароль сайту в адмінці і додайте HTTPS (див. розділ вище).
- Логін/пароль `admin`/`admin` за замовчуванням — змініть їх одразу в адмінці після першого запуску.
- Для завантаження контенту дотримуйтесь умов використання відповідних сайтів та авторських прав.
